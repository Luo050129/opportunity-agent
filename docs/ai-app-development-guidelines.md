# AI 应用开发通用技术指南（从本项目提炼，可用于下一个项目）

适用场景：需要**可信输出**的 LLM 应用（结构化抽取、合规审核、单据处理、Agent 工作流）。
下面每条都对应本项目里真实用到的做法与踩过的坑，可以直接当新项目的架构基线。

## 0. 一句话原则

**把"需要下结论、必须可解释"的部分交给确定性组件，把"语言理解、调度"交给模型；模型永远不能是唯一判定来源。**

## 1. 第一步就定"判定权归属"

| 问题 | 决策 |
| --- | --- |
| 谁产出业务结论（字段值、状态、合规判定）？ | 确定性规则/工具 |
| 谁负责理解自由文本、选择调用路径？ | 模型，且只在这两件事上 |
| 模型输出能直接落库吗？ | 绝不；必须经工具产物或校验之后才落盘 |

落地形式：**规则引擎 = 工具集，模型 = 规划器 + 文案润色器**。
既回答得了"依据是什么"（规则 ID + 原话），也能在模型不可用时保持可用。

## 2. 上下文管理：双轨上下文

- **引擎轨**：完整原文 + 全部历史，保证召回与证据完整；
- **模型轨**：压缩摘要（头尾截断、只给状态与缺口），控制 token 与成本；
- 压缩**只作用于模型侧**，并回传统计（原文长度/上下文长度/省略字数/证据条数），让"压缩是否失真"可观测；
- 会话尽量无状态：调用方每次回传完整上下文，服务端不存会话，天然支持多窗口与重启。

## 3. 工具契约化（Tool Contract）

每个工具声明四件事，编排器据此保证正确性：

1. `name` / `description`：给模型看的可读语义；
2. `parameters`：JSON Schema，避免自由文本入参；
3. `requires`：依赖哪些前置产物；
4. `produces` + `optional`：产出什么、是否可选增强。

规则：

- 工具必须**确定性、幂等**，同输入同输出；
- 工具不做"猜测"，拿不到前置产物就返回 `skipped`，而不是抛异常；
- 新增能力 = 新增契约，不改编排逻辑（本项目从 8 个工具扩到 10 个，编排器零改动）。

## 4. 规划器与编排器分离

```
Planner(模型) → 计划 → Orchestrator(代码) 校验 → Executor 执行 → 产物校验 → 兜底
```

编排器必须做这 5 件事，缺一不可：

1. **白名单**：计划里出现未注册工具直接拒绝并记录；
2. **依赖补齐**：按 `requires` 递归插入前置工具，保证计划拓扑可执行；
3. **必需项兜底**：模型漏掉必需工具时自动补上；
4. **步数上限**：防止模型给出无限长计划；
5. **产物校验 + 一次兜底重跑**：缺产物时补齐，而不是让结果残缺。

一句话：**让模型决定顺序，让代码保证正确性**。

## 5. 输出契约：三态 + 证据 + 无法判断原因

每个字段返回 `{value, status, evidence[], notes[], rule_refs[]}`：

- `status ∈ {事实, 推断, 未确认}`，未确认时 `value = null`（**宁缺勿编**）；
- `evidence` 保留原话与来源（原文 / 追问第 N 轮），可回溯；
- 判不了就显式输出 `cannot_judge_reason` + 「建议人工复核」，绝不静默给一个"看起来合理"的值；
- 前后矛盾时**双方同时保留**，不替用户选边。

## 6. 失败与降级设计（直接抄这条链）

```
模型不可用        → 规则默认编排
模型给出非法计划  → 拒绝 + 补齐 + 记录
单工具异常        → 该步标 error，流程继续，最后兜底补齐
连续 2 次调用失败 → 熔断 60s，避免每个请求都干等超时
文件解析失败      → 明确错误 + 可操作建议（"请粘贴文本"）
输入过短/无关     → 全部字段标未确认 + 列出未被规则覆盖的内容
```

关键点：**每种失败都要有"用户看得懂的下一步"**，而不是报错栈。

## 7. 可观测性：把 plan / trace / context 当一等输出

- `plan`：本次编排来自模型还是兜底、模型给的编排理由、被拒绝的工具；
- `trace`：逐步记录工具名、选择理由、状态、耗时、产物摘要；
- `context`：上下文预算统计；
- 界面把它可视化（本项目「执行轨迹」面板）。

收益：排障、评审、演示三项复用同一份数据，不需要额外写报告。

## 8. 测试策略

| 层次 | 做法 |
| --- | --- |
| 规则正反例 | 每条硬规则至少一正一反（"可能下周给报价"不得写成事实、"合同正在走流程"不得判赢单） |
| 样例驱动 | 每个典型输入固定断言到字段级（本项目 5 个样例文件） |
| 模型打桩 | 用桩替换模型，覆盖"合法计划 / 非法计划 / 调用失败 / 熔断"四分支，测试不依赖网络 |
| 数据生成器 | 测试数据用脚本生成（本项目 docx 生成器），保证可重建、可改内容 |
| 反向断言 | 断言"输出里不得出现凭空金额/姓名"，比断言"输出对不对"更能抓幻觉 |
| 接口冒烟 | 起真实服务跑 `/api/*`，覆盖上传与解析失败路径 |

## 9. 成本与延迟预算

- 把模型调用压到**每请求 1–2 次**（本项目：1 次规划 + 1 次润色），其余全是本地毫秒级计算；
- 明确超时（本项目 15s）、熔断、`max_tokens` 预算，并记录 usage；
- 推理模型注意：`reasoning_content` 先吃 token 预算，`max_tokens` 给小了会出现"有 usage、正文为空"的假成功；
- 对"必须快"的场景（现场演示、批量导入）默认关闭模型，需要时再开。

## 10. 安全与合规

- **密钥不进仓库**：放被 `.gitignore` 忽略的本地配置或环境变量；日志只打印掩码；
- **提示词注入边界**：把不可信文本放在"数据位"而不是"指令位"。本项目判定面天然免疫（原文只进规则引擎），但润色面仍把字段值送进模型，是需要额外校验的薄弱点；
- 不把模型输出直接写生产系统：先落"待人工确认"，再走校验或审批；
- 记录规则版本与模型版本，让结论可复现。

## 11. 演示与交付工程（评审场景的隐形评分项）

- **一键入口**：双击即启动，端口被占用自动顺延，失败窗口不消失并给可操作提示；
- **零依赖优先**：能不用第三方库就不用，现场断网、环境没装包都能跑（本项目只用 Python 标准库）；
- **内置样例**：评委不用自己想输入，点一下就有可验证的结果；
- **交付物齐全**：可用入口 + 使用说明 + 规则使用说明 + 输出格式说明 + 自测样例；
- **把"无法判断"做成一等功能**：主动展示哪些内容没有规则覆盖，比装作什么都能答更可信。

## 12. 平台与环境坑（Windows 尤其容易踩）

| 现象 | 根因 | 修法 |
| --- | --- | --- |
| 批处理双击报 `'xxx' is not recognized`、命令被截断 | cmd.exe 在 `chcp` 后按字节偏移重读 .bat，非 ASCII 行被破坏 | .bat 保持纯 ASCII，中文提示交给 Python 输出 |
| 第二个进程绑同一端口却"都启动成功" | Windows `SO_REUSEADDR` 允许重复绑定 | 绑定前主动 `connect` 探测端口占用 |
| 控制台没有输出 | 非 TTY 时 Python 输出块缓冲 | `PYTHONUNBUFFERED=1` + 关键日志 `flush=True` |
| 环境没有浏览器 | 无法做可视化验收 | 退化为"接口冒烟 + 静态一致性检查 + 语法检查"，并如实说明限制 |
